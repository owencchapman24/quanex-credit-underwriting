# Phase 11 methodology

Phase 11 is a release-quality layer over the approved Phase 0-10 underwriting record. The bounded post-Phase 11 remediation adds no analytical evidence and changes no coded recommendation, selected structure, operating assumption, scenario, covenant, lender EBITDA, or recovery conclusion. It corrects date alignment, sensitivity mechanics, missing-data behavior, dynamic-test evidence, independent invariants, leverage labels, and decision-facing presentation. The information cutoff remains December 15, 2025 and the closing remains hypothetical at January 31, 2026.

The workflow inventories the software actually used, resolves internal repository links, hashes decision-facing artifacts, verifies cross-deliverable anchors, and rebuilds approved outputs in a disposable local clone. Clean-release verification requires an explicitly selected commit, a pristine source checkout, and zero overlays. A separate pre-commit overlay-review mode requires an explicit base commit and a one-path-per-line manifest that exactly equals the working-tree change set; it is labeled pre-commit evidence and cannot establish clean-release success. The clone is created with `--no-checkout`, stores `core.autocrlf=false` in its own repository configuration, and only then materializes the selected commit as the disposable clone's local `main` branch. This preserves the earlier-phase branch gate without changing any source or remote branch, and the initial disposable tree comes solely from canonical committed content. The harness verifies the seven Phase 3 control files against their Git blobs immediately after checkout. It then uses Git—not the source worktree—to apply the documented Windows generated-text profile only to Markdown and JSON paths actually rewritten by the Phase 0-10 build, including the README and report sources. Static Phase 0 evidence hashed by Phase 10, maintained Phase 11 source documents, and CSV remain canonical LF. No unmodified path is copied from the live source tree. In overlay-review mode only the declared inventory is copied from the live working tree, byte-for-byte; the inventory is never inferred from Git status. CSV, JSON, Markdown, PNG, PDF, and canonicalized XLSX artifacts are compared byte-for-byte after reproduction, without comparison-time EOL normalization or semantic substitution. Fresh Phase 8, Phase 9, and Phase 10 validation outputs are compared immediately after the step that writes them and before a later step could overwrite them; no validation snapshot is restored. The workbook is also compared by its approved normalized analytical fingerprint and by sheet order, formulas, resolved shared-string text, values, formats, meaningful drawing placement, charts, data validation, names, calculation settings, scenario captures, and saved Base scenario. Deterministic XLSX package canonicalization makes the final raw workbook identity part of the exact release criterion.

`python -B scripts/phase11.py all --base <sha> --overlay-manifest <path>` first requires that manifest to equal the pre-generation working tree, then writes only its fixed `data/phase11/processed` outputs and `docs/phase-11/SOURCE_LEDGER.csv`; no other path may newly join the internal build inventory. Refresh the external manifest from the final status before running read-only `validate` and `verify-overlay`, both of which require an exact inventory. `verify-release --commit <sha>` creates a no-hardlinks disposable clone with independent Git metadata and clone-local canonical-LF configuration, uses only the selected clean commit, executes the complete release gate with zero overlays, removes the clone, and compares the source repository manifest, HEAD, and Git status before and after. Neither system nor global Git configuration is changed.

Release QA distinguishes mechanical reproducibility from human judgment. Debt-document interpretation, EBITDA adjustments, scenario severity, accessible cash, facility sizing, covenant design, recovery limits, and the Conditional Approval recommendation remain owner-reviewed judgments; a successful build does not re-approve them.

The October 31, 2025 historical debt reference is kept separate from the January 31, 2026 projected alternatives. Phase 7 candidate pairings govern term-sizing rows, and amortization cases rerun the Phase 7 integrated engine. An unrun dynamic spreadsheet test cannot pass; its evidence is recorded separately and tied to the current scripts and source signature. The exact remediation-path allowlist is enumerated in `scripts/phase11.py` rather than implemented as a broad prior-phase exception.

The AI-use and analytical-ownership disclosure is `owner_reviewed`; licensing remains a separate pending owner decision and is not a technical validation failure.

Phase 11 includes no Phase 12 interview narrative or final-release action.
