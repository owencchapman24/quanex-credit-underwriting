# Phase 11 methodology

Phase 11 is a release-quality layer over the approved Phase 0-10 underwriting record. The bounded post-Phase 11 remediation adds no analytical evidence and changes no coded recommendation, selected structure, operating assumption, scenario, covenant, lender EBITDA, or recovery conclusion. It corrects date alignment, sensitivity mechanics, missing-data behavior, dynamic-test evidence, independent invariants, leverage labels, and decision-facing presentation. The information cutoff remains December 15, 2025 and the closing remains hypothetical at January 31, 2026.

The workflow inventories the software actually used, resolves internal repository links, hashes decision-facing artifacts, verifies cross-deliverable anchors, and rebuilds approved outputs in a disposable local clone. The clone stores `core.autocrlf=false` in its own repository configuration as part of `git clone`, so the setting is effective before the initial checkout and canonical LF CSV blobs are not converted by Windows Git. The harness verifies the seven Phase 3 control files against their Git blobs immediately after checkout. For each unmodified tracked path, the approved live byte form must then be either exactly the canonical Git blob or exactly that blob's LF-to-CRLF checkout representation; only the latter is rematerialized from Git with command-local `core.autocrlf=true`. Any other non-overlay difference fails. The stored clone-local setting remains `false`, and no file becomes an analytical exception. Only the fixed 62-path remediation inventory is copied from the live working tree, byte-for-byte; the exception set is not inferred from Git status. CSV, JSON, Markdown, PNG, and PDF artifacts are still compared byte-for-byte after reproduction, without comparison-time EOL normalization or semantic substitution. The workbook is compared by its approved normalized analytical fingerprint and by sheet order, formulas, values, formats, charts, data validation, names, calculation settings, scenario captures, and saved Base scenario. Raw XLSX ZIP identity is recorded but is not the semantic pass criterion because calculation engines can rewrite non-analytical metadata.

`python -B scripts/phase11.py all` writes only `data/phase11/processed` and `docs/phase-11/SOURCE_LEDGER.csv`. It performs the write-producing build in a disposable clone. `validate` is read-only. `verify-isolated` creates another no-hardlinks disposable clone with independent Git metadata and clone-local canonical-LF configuration, overlays the exact authorized review files, makes a temporary local verification commit, executes the complete release gate there, removes the clone, and compares the authoritative repository manifest and Git status before and after. Neither system nor global Git configuration is changed.

Release QA distinguishes mechanical reproducibility from human judgment. Debt-document interpretation, EBITDA adjustments, scenario severity, accessible cash, facility sizing, covenant design, recovery limits, and the Conditional Approval recommendation remain owner-reviewed judgments; a successful build does not re-approve them.

The October 31, 2025 historical debt reference is kept separate from the January 31, 2026 projected alternatives. Phase 7 candidate pairings govern term-sizing rows, and amortization cases rerun the Phase 7 integrated engine. An unrun dynamic spreadsheet test cannot pass; its evidence is recorded separately and tied to the current scripts and source signature. The exact remediation-path allowlist is enumerated in `scripts/phase11.py` rather than implemented as a broad prior-phase exception.

The AI-use and analytical-ownership disclosure is `owner_reviewed`; licensing remains a separate pending owner decision and is not a technical validation failure.

Phase 11 includes no Phase 12 interview narrative or final-release action.
